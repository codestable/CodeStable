# Epic 共享语言

只在新词、重载词或相邻概念边界会改变目标、范围、事实权威、生命周期、验收或子项契约时使用。
它让 proposed Epic 对 owner、reviewer 与执行者表达同一件事，不负责建立一套与项目文档竞争的词典。

## 建模与归属

- 先查项目已有 glossary、domain 文档、需求、ADR、代码、schema 与测试。已有 canonical 定义只链接；
  冲突必须显式提出，不能在 Epic 里静默改义。
- 领域术语定义业务概念本身，排除同义词与相邻概念；架构角色定义本路线中的责任、事实权威、输入输出
  与不变量。实现技术名不因出现在设计中自动成为领域术语。
- 仓库事实走 `AFK`，由 agent 核实；产品含义或概念边界走 `HITL`，由 owner 在事实、选项、取舍与
  建议齐备后决定。术语歧义不新增状态：暂时不能精确提问时留在 `尚未明确`，能够精确提问后进入
  现有 `待决策`。

条件式 `## 共享语言与概念边界` 使用最小格式：

```markdown
- **{canonical 术语}**：{一两句紧凑定义}
  - 不包括：{相邻概念或禁用同义词}
  - 关系 / 不变量：{owner、事实权威、输入输出或边界}
  - 来源：{canonical 文档、代码证据或待决策名称}
```

概念之间存在流程或状态关系时，至少补一条具体的端到端或边界场景，写清输入、变化与可观察结果。
纯词典无法证明关系已经对齐；场景出现两种合理解释时，继续 AFK 调查或 HITL，而不是冻结路线。

## Language Clear

共享语言清晰必须同时满足：

- 每个会改变路线的术语已定义或链接，全文同一术语保持同一含义；
- 相邻概念的排除边界、责任与关键不变量一致，没有靠未声明同义词切换含义；
- 子项契约沿用相同词汇，一个不了解讨论过程的执行者能从定义与场景判断交付边界；
- owner 对产品含义或概念边界的 HITL 已解决；可核实事实没有被上交给 owner。

Language Clear 是 Route Clear 的组成部分，不是新的 owner gate。owner 在 review 后询问术语且暴露了
目标、范围、权威、验收或子项边界的不同理解时，候选尚未清晰，必须更新永久 Epic 并按原契约规则
重新 review/确认；只解释不进入 owner 契约的实现细节时不重开设计。

跨任务稳定的领域术语毕业到项目已有 canonical 领域文档；没有归宿时先留在永久 Epic 并给出建议
落点，owner 可在既有 gate 或后续治理中选择；未选择归宿不阻塞当前 Epic，也不自动创建 `CONTEXT.md`、
glossary 或第三套真相。架构角色留在 Epic，难回退且来自真实取舍的结构性决定才进入 ADR。
